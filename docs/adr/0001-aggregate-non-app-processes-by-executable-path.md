# 非 app 行程改以執行檔路徑聚合

記憶體排行原本只彙總 `.app` 包內的行程,非 app 行程一律以 pid 各自成列(程式碼註解稱「避免把互不相干的同名行程誤加總」)。我們改為讓非 app 行程比照 app,以**執行檔路徑**為聚合鍵一併加總。

**為什麼:** 舊規則會漏報最該被看見的東西——實測某台機器上 `node` 分成 36 個行程共 ~1.6GB、`claude` 分成多列,單顆都擠不進前五,於是全機第二大的記憶體消費者完全不出現在排行上;而 app 那邊 27 個 Chrome Renderer 早就被加總成一列且無人視為「誤加總」。標準不一致沒有正當理由:同一份路徑,在 `.app` 內就聚合、不在就不聚合,但「同路徑=同程式的多個行程」的成立程度兩邊一樣。原註解擔心的是「同**名**誤加總」,而聚合鍵用的是完整路徑,比同名嚴格得多;實測非 app 行程同名不同路徑者為 0 筆。

**取捨與後果:** 這推翻了 `testKeepsNonAppProcessesSeparate` 的原始意圖(已改寫為「同路徑才聚合、不同路徑仍分開」),也讓本次改動從單純「加分類標籤」擴大為「同時修分組」。查看群組內各子行程明細,交由 ROADMAP 已規劃的 row expansion 處理。
